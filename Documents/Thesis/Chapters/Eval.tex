\section{Report Generation System}
\label{sec:report_system}

The implementation includes an automated report generation system that captures events throughout the production lifecycle. Two report types are generated:

\subsection{Production Reports}

The \texttt{ReportCollector} class aggregates events from the Production Agent and generates comprehensive reports for each production run. Reports are saved in both human-readable text format and machine-parseable JSON format.

\textbf{Event Types Captured:}
\begin{itemize}
    \item \texttt{SYSTEM\_START} / \texttt{JOB\_COMPLETED}: Production run boundaries
    \item \texttt{CFP\_RECEIVED} / \texttt{CFP\_RESPONSE}: Negotiation events
    \item \texttt{RESOURCE\_SELECTED}: Winner selection
    \item \texttt{EXECUTION\_STARTED} / \texttt{OPERATION\_COMPLETED}: Task execution
    \item \texttt{AAS\_UPDATED}: Submodel modifications
\end{itemize}
\subsection{Simulator Reports}

Each simulator generates independent reports tracking machine utilization, operation counts, and processing times. These reports enable verification of skill execution and timing analysis.

\textbf{Partial Implementations.} Two requirements use alternative approaches:
\begin{itemize}
    \item REQ\_15 and REQ\_24 (FIPA ACL): XMPP PubSub was used instead of pure FIPA ACL, while maintaining equivalent Contract Net Protocol semantics.

\begin{itemize}

    \item REQ\_28 (Services Catalog): Cataloging functionality deferred as out of scope for the proof-of-concept.
\end{itemize}

These deferrals do not impact the validation of the Type 3 \ac{AAS} concept, as the core autonomous behavior, negotiation, and execution tracking capabilities are fully demonstrated.
\section{Discussion}
\label{sec:evaluation_discussion}

\subsection{Achievements}

The evaluation demonstrates that the Type 3 \ac{AAS} concept is feasible and can be implemented using existing open-source tools. Key achievements include:

\begin{itemize}
    \item \textbf{BDI-AAS Integration}: Successfully integrated BDI agent reasoning with \ac{AAS} data models, enabling agents to use submodel data as beliefs and update submodels based on intentions.
    
    \item \textbf{Contract Net Protocol}: Implemented multi-agent negotiation for resource allocation, with the Production Agent successfully coordinating with multiple Resource Agents.
    
    \item \textbf{Real-time AAS Updates}: Demonstrated that the \ac{AAS} can serve as a live digital twin, with submodel elements updated during task execution.
    
    \item \textbf{Skill Invocation}: Validated the invocationDelegation pattern for connecting \ac{AAS} Operations to external execution systems.
\end{itemize}

\subsection{Limitations}

Several limitations were identified during evaluation:

\begin{itemize}
    \item \textbf{Simulation Only}: The evaluation used simulated machines rather than physical hardware, limiting validation of real-world timing and error handling.
    
    \item \textbf{Single Production Scenario}: Only the drill-and-move scenario was tested; more complex process plans would require additional validation.
    
    \item \textbf{SPADE Framework Constraints}: The SPADE BDI implementation has limitations (e.g., belief storage), requiring workarounds documented in Chapter~\ref{chap:implementation}.
    
    \item \textbf{No Performance Benchmarking}: The evaluation focused on functional correctness rather than performance metrics like throughput or latency under load.
\end{itemize}

\subsection{Validation of Thesis Contributions}

The evaluation results validate the three main contributions of this thesis:

\textbf{Contribution 1: Bidirectional AAS Integration.} The test runs demonstrate that agents both read from and write to the \ac{AAS}. During initialization, Resource Agents load beliefs from the Operational State, Knowledge, and Capability Submodels. During execution, agents invoke Operations via the \texttt{invocationDelegation} pattern (e.g., \texttt{invoke\_drill()}, \texttt{invoke\_movexy()}), and the Production Agent updates the Execution Tracking Submodel in real-time. Table~\ref{tab:aas_updates} shows eight submodel updates during a single production run, confirming the bidirectional data flow between agents and their \ac{AAS} representations.

\textbf{Contribution 2: Foundational Submodels for Proactive Behavior.} The implemented submodels successfully support agent-based decision-making while maintaining compliance with the \ac{AAS} meta-model. The Capability Submodel provides skill descriptions that agents use to respond to CFP requests. The Process Plan Submodel defines goals (Entry\_Point, Exit\_Point) and required capabilities that guide the Production Agent's orchestration logic. The Knowledge and Interaction Submodels store behavioral parameters such as resource constraints and time slot availability that inform negotiation responses. All submodel structures use standard \ac{AAS} elements (Property, SubmodelElementCollection, Operation), demonstrating that proactive agent behavior can be supported without extending the \ac{AAS} specification.

\textbf{Contribution 3: Proof-of-Concept with Production Resources.} The drill machine scenario validates the feasibility of implementing BDI-based Type 3 \ac{AAS} in a production context. The test runs show successful Contract Net Protocol negotiations between multiple Resource Agents, coordinated task execution following a process plan (Move $\rightarrow$ Drill), and real-time tracking updates. While the evaluation uses discrete-event simulators rather than physical hardware, the simulators implement the same \ac{AAS} interfaces (invocationDelegation via HTTP) that would be used with real PLCs or machine controllers. This design ensures that transitioning to physical hardware requires only endpoint URL changes, not architectural modifications.

\section{Summary}

The evaluation validates that the Type 3 \ac{AAS} prototype meets its functional and non-functional requirements. The automated report generation system provides comprehensive traceability of system behavior, and all test runs completed successfully. While limitations exist, particularly regarding physical hardware testing and performance benchmarking, the prototype demonstrates the feasibility of integrating BDI agents with the Asset Administration Shell for autonomous manufacturing coordination.
